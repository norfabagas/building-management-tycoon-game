# Construction activity, building names and clean rooftops — 2026-10-21

The user requests animation during initial construction and upgrades, naming every building, and removal of the block on each rooftop. Retain existing gameplay and DRY/YAGNI/KISS: no new economy, engine, dependency or generated artwork.

## Construction presentation

BuildingWork derives presentation from the existing ConstructionStage and UpgradeOrder. Initial queued/paid/shell/shell-done/basement states and every pending upgrade have a temporary worksite. Completed construction waiting for Open to Business has no worksite; an open building without an upgrade has none. Queued jobs show a steady scaffold/hoist with a gently breathing safety light; the hoist and dust move only during shell/basement or UpgradeStage.building. Basement work stays near ground level. Elevated work uses completed storeys, with a temporary scaffold extension for an unfinished floor; actual height/capacity only increases through the unchanged domain completion rule.

A separate ConstructionActivityPainter uses the existing 30fps cosmetic activity clock and repaint boundary, not game time/financial transactions. Draw outline scaffolding, a mast/arm with moving rope/hook and gently fading dust; there is no permanent rooftop payload. Project anchors through the same rotated/zoomed world camera and clip against foreground building silhouettes. Work labels expose their true stage to accessibility. Reduced motion and hidden/TickerMode maps suspend the shared clock; construction completion/cancellation removes the work overlay. Open-business people/cars continue during upgrades. Static facade/terrain layers do not repaint on each activity tick. Physical GPU/frame-rate behavior requires device testing.

## Rename flow and persistence

Every selected building, including queued/active construction or upgrade, has a 48px Rename building pencil beside its fixed title/Upgrade action. The themed GameReviewDialog shows the building type/ID, editable current name, Cancel and Save name. It scrolls above pinned actions/keyboard. The map scaffold stays at its original size behind the dialog, avoiding a background panel overflow when a failed-save message appears with the keyboard open. Cancel does not rename. Blank, over-40-code-point and control/newline-containing names are rejected; outer whitespace is trimmed, Unicode and duplicate display names are allowed. IDs remain the identity for selections, tenant references, jobs, road access and all domain operations. A custom name is free and has no effect on rent, cost, progress, limits or achievements. Long map labels wrap to two lines with an ellipsis.

ApartmentBuilding owns one optional private custom name and shared validation. All existing consumers use its name getter, preserving the default type/ID label for unnamed buildings and updating map/directory/interior/upgrade labels consistently. DistrictViewModel commits DistrictSimulation.renameBuilding through the existing repository transaction. Failed saves keep the prior game/name and show inline retry; pending writes disable editing, duplicate submission, Cancel and back dismissal.

Save schema **9**, catalog 2 persists customName. Schemas 1–8 remain readable; schema-8 roads, geometry, balances, units, job state and time are preserved and written as 9 by the normal transaction. An old app that only supports schema 8 rejects the newer save instead of dropping renamed fields on its next write. Keep local storage and use the existing timestamp Sync updater; close old game tabs before updating. Profile catalog/slot count and database stores remain unchanged. Malformed name fields reject the snapshot without overwriting it. Names are local data and are never transmitted to a service.
