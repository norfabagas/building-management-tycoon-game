# Camera rotation and building action UX

Implemented for the 2026-10-18 follow-up about Upgrade building, crosses and missing map rotation.

## Player experience

The selected building has a fixed cream header with its name and green Upgrade building action. It remains visible while room/detail content scrolls. In the upgrade catalog, the header shows the building name and Upgrades with a neutral Back to floors action, replacing the duplicated scrolling header. Header actions wrap within a bounded share of available width and retain at least 48px targets, including 320px screens at 140% text. Navigation remains available during ordinary local autosaves; committing an upgrade still uses the existing guarded transaction. Exit building is the single building exit at the bottom, alongside neutral outlined Go up/down buttons. The redundant cross beside the building name is removed. Theme controls use standard visual density and padded tap targets, including explicit GameButton/IconButton styles, so Web desktop defaults cannot shrink the requested 48px controls to 40px.

Other district panels retain the Close panel tooltip and now show a 48px icon-plus-Close button. Green Confirm upgrade/Confirm acceleration controls distinguish financial decisions from Cancel. Existing custom tenant release and local-profile deletion flows stay intact.

The compass next to Main road opens labelled Rotate left, Rotate right and Reset rotation controls plus the current bearing. Button turns are 90 degrees; Reset returns to zero yaw without moving the world point at the viewport centre or changing zoom. Two fingers can twist continuously while pinching/panning. A two-finger gesture restores the prior drawing preview and suppresses single-finger drawing/selection until all fingers lift. Main road focuses the highway at the current bearing and zoom. Center map resets pan and bearing while retaining zoom. Orientation is session state and survives entering/exiting buildings, panels and viewport changes; it is not a persisted save setting.

## Rendering and architecture

MapCameraViewModel owns yaw in radians, normalised to one turn, alongside pan/zoom. Project the rotated world XY plane through the existing isometric matrix, leaving architectural Z vertical. Inverse-transform pointers back into original world coordinates for land selection, road tests, preview and building picking. The combined focal transform uses I·R·I⁻¹, zoom ratio and the projection's vertical origin offset so the touched world point stays under the fingers. The same transform anchors compass rotation/reset at the viewport centre. Capture the two-pointer focal point at pointer-down before gesture-recognition slop, and derive the origin offset from the current camera zoom for each event, including events delivered before the next frame. Combined twist/pinch/pan tests retain the focal world point within 0.01px.

Flat terrain/road atlas textures use the matching ground-plane affine transform, while highway geometry uses projected original world coordinates. Order facade/roof corners by their position in the rotated view, derive visible edge lengths from original world coordinates and choose ground-depth order for both rendering and reverse-order picking. Continue repeating approved facade strips by completed floor count; place service equipment on the correct facing edges. Labels and decoration/construction billboards remain upright.

Traffic positions follow original world routes projected by the rotated camera. Add camera yaw to local volumetric figure headings; rotate face normals before culling/shading. Invalidate traffic/occlusion caches when yaw changes. Cast a ray from each actor toward the camera through footprint slabs before erasing occluded pixels with the same rotated building silhouette; this preserves front-side actors for every bearing.

No changes to domain economy, road access rules, geometry in saved snapshots, five save slots, schema 8/catalog 2, artwork references/bytes or BM master. All runtime resources and saves remain local.

## Material limitations

This is horizontal isometric orbit/yaw, not free pitch/tilt or perspective flight. Approved artwork provides two facade families; opposite visible walls reuse those strips rather than inventing unique rear artwork. Decorations and construction symbols are upright billboards. Daylight remains the existing screen-space atmospheric gradient. Session camera orientation resets when the district route is recreated. Automated two-pointer tests establish gesture correctness; desktop browser pointer QA does not certify a physical Android touchscreen or GPU performance. Android SDK availability is recorded with final validation.
